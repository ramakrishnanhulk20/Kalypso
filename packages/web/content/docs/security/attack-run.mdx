Anyone can run this. It needs Node.js 22.9 or later and a clone of the repo, and no Kalypso key: build the core library, then run `npm run prove:testnet` from `packages/contracts/scripts`, as shown under "Run it yourself" below. A stranger's run checks the amounts with the published demo accountant key and ends with 12 passed and 1 skipped. What follows is the record of the last full run, copied from [`docs/security/attack-run.md`](https://github.com/ramakrishnanhulk20/Kalypso/blob/main/docs/security/attack-run.md).

Kalypso's prove-it command attacks the product's own promises against the live showcase company on Stellar testnet, then prints what each attack tried and what stopped it. It signs nothing with any showcase key: every attack on the showcase is a read or a simulation of current testnet state. Only P11 sends transactions, from throwaway friendbot accounts it makes and forgets, so anyone can run it without keys.

## Run it yourself

```sh
cd packages/core && npm ci && npm run build
cd ../contracts/scripts && npm ci
npm run prove:testnet
```

Add `-- --archive <url>` to read the showcase's history from a Kalypso event archive (https only); the archive URL goes in the README after deploy.

This run had the seed's private file, so it also checked every decrypted amount against what the seed paid and opened a worker's own payslips. Without that file, the amounts come from the published demo accountant key and the worker half of P10 is skipped, so a stranger's run ends with 12 passed and 1 skipped.

## What this run does not cover

- Only amounts are private. Who pays whom, when, and who is on a roster are public by design (threat model, non-goals).
- The history checks (P1, P2, P3, P9 and P10) read RPC's last 7 days unless `--archive` is given. This run read RPC only. Once the showcase's first ledger 5084191, or for P9 the token's first ledger 5083382, falls outside that window, they fail and say why; they never pass on missing history.
- P1 looks for each salary in 15 encodings. It does not try to break the encryption itself; P3 shows that a wrong key reads nothing.
- Every attack on the showcase is a simulation of what the network would do with each transaction, and none was submitted. P11's two transactions come from its own throwaway accounts, and each run leaves one more auditor id and one more token account behind.
