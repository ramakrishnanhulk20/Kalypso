Necesitas Git, Node.js 24 (el servidor necesita 24; los scripts de testnet necesitan 22.9 o posterior), una cadena de herramientas de Rust para los contratos (CI usa Rust 1.99.0) y la [stellar CLI](https://github.com/stellar/stellar-cli) 28.1.0 para la comprobación de la atestación de compilación.

```bash
git clone https://github.com/ramakrishnanhulk20/Kalypso.git
cd Kalypso
```

Cada bloque de comandos de abajo parte desde la raíz del repositorio.

## Ejecuta los tests

El 11 de octubre las suites tenían 115 tests de nómina y 43 de auditoría (`cargo test`), 560 tests del core con 98,47 % de cobertura de líneas, 352 tests del servidor con 98,31 %, 674 tests de la app web y 11 tests de los scripts de testnet, 1755 en total. Los 352 del servidor también se ejecutan una segunda vez con el driver de Postgres de producción, con `npm run test:wire`.

```bash
cd packages/contracts && cargo test
```






## Comprueba el stack desde el estado de la cadena [#check-the-stack-from-chain-state]

`check:testnet` lee el estado de la cadena y ejecuta 18 comprobaciones: nadie, nosotros incluidos, puede cambiar qué pruebas acepta el verificador; ninguno de nuestros contratos tiene administrador ni vía de actualización; el código en la cadena es el código publicado; y cada contrato tiene al menos 14 días antes de archivarse. Necesita el contrato de nómina de la versión v0.1.1 y el registro de auditoría de la versión v0.1.0, cada uno en su propia carpeta:

```bash
mkdir -p release/v0.1.1 release/v0.1.0
curl -fL -o release/v0.1.1/kalypso_payroll.wasm https://github.com/ramakrishnanhulk20/Kalypso/releases/download/v0.1.1/kalypso_payroll.wasm
curl -fL -o release/v0.1.0/kalypso_auditor.wasm https://github.com/ramakrishnanhulk20/Kalypso/releases/download/v0.1.0/kalypso_auditor.wasm
cd packages/contracts/scripts && npm ci
npm run check:testnet -- --wasm-dir ../../../release/v0.1.1 --auditor-wasm-dir ../../../release/v0.1.0
```

Los mismos archivos están en la [página de Releases](https://github.com/ramakrishnanhulk20/Kalypso/releases). Una ejecución que pasa termina con `18 of 18 checks passed. RESULT: PASS`.

## Ataca la empresa de muestra

`prove:testnet` ataca las promesas de la empresa de muestra en testnet e imprime qué detuvo cada ataque. Ejecuta 13 comprobaciones y no necesita claves.

```bash
cd packages/core && npm ci && npm run build
cd ../contracts/scripts && npm ci && npm run prove:testnet -- --archive https://kalypso-payroll.vercel.app/api/archive/
```

Sin el archivo privado de la semilla, los montos se comprueban con la clave de contador de demostración publicada y se omite la mitad del trabajador de P10, así que la ejecución de un desconocido termina con 12 aprobadas y 1 omitida. Las comprobaciones de historial leen RPC, que conserva cerca de los últimos 7 días. La opción `--archive` de arriba lee ledgers más antiguos del archivo de eventos en vivo de Kalypso, así que las comprobaciones de historial siguen funcionando después de esa ventana; su estado es público en [/api/archive/v1/health](https://kalypso-payroll.vercel.app/api/archive/v1/health). La última ejecución completa está en [Informe del ataque](/docs/security/attack-run).

## Mantén el stack vivo

```bash
cd packages/contracts/scripts && npm ci && npm run keepalive:testnet
```

Esto extiende la vida de almacenamiento de los cuatro contratos y de su código, 60 días por defecto (`-- --days <n>` para cambiarlo), para que ninguno se archive mientras tú y otros visitantes lo están viendo. Cualquiera puede pagar una extensión y no cambia nada más. Paga desde la identidad de la stellar CLI que nombra `DEPLOYER` (por defecto `kalypso-deployer`) en `packages/contracts/.stellar`, que debe existir y tener XLM de testnet. `check:testnet` falla cuando a algún contrato le quedan menos de 14 días.
